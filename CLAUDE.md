# AvatarStudio — инструкции проекта для Claude Code

## Что это
Платформа генерации видео с ИИ-аватарами (класс HeyGen). Полное ТЗ — в `docs/TZ_AvatarStudio_v2.md`, критика ТЗ — в `docs/Критика_ТЗ.md`. Читай оба перед любой архитектурной задачей.

## Ключевое стратегическое решение (ветка C)
MVP строится на **коммерческих API** для ML-ядра, за единым внутренним контрактом:
- **TTS**: провайдер за интерфейсом `ITTSProvider` (текст+markup → audio + word/phoneme alignment). Alignment, которого не даёт провайдер, добирается forced-aligner'ом (Montreal Forced Aligner / ctc-segmentation) как отдельным шагом пайплайна.
- **Липсинк/аватар**: за интерфейсом `IAvatarDriver`. Первая реализация — коммерческий API; своя модель подключится позже без переписывания.
- Ни одна бизнес-логика не должна знать, какой провайдер под капотом.

## Стек (зафиксирован)
- **Frontend**: React + TypeScript + Vite, Zustand, PixiJS для canvas-превью редактора.
- **Backend**: Node.js (NestJS), PostgreSQL (+ JSONB для слоёв сцен), Redis (очереди BullMQ на MVP; миграция на Temporal — отдельная задача после стабилизации DAG).
- **Хранилище**: S3-совместимое (MinIO локально), presigned uploads.
- **Медиа**: FFmpeg (композитинг filter_complex, кодирование).
- Монорепо: pnpm workspaces — `apps/web`, `apps/api`, `apps/worker`, `packages/shared`.

## Неизменяемые правила (из ТЗ, раздел 0.3)
1. **Consent-gate, C2PA-манифест, модерация скриптов — в MVP, не в бэклоге.** Любой рендер без C2PA-шага — баг.
2. **Язык — параметр конфигурации, не ветка кода.** Никаких `if (lang === 'uz')`.
3. **Scene-cache обязателен**: content_hash сцены = SHA-256(script + markup + voice_id + avatar_id + layers + render_params). Правка одной сцены из N пересчитывает одну сцену.
4. Кредиты: резервирование при постановке в очередь, автовозврат при сбое/отмене. Списание — только по факту `done`.
5. Ошибки пользователю — человекочитаемые, с подсказкой действия.
6. Все числовые утверждения о производительности в коде/доках помечать: [факт]/[оценка]/[допущение].

## Director Markup (дифференциатор D1)
Собственный синтаксис поверх текста: `[pause:1.2s]`, `[emphasis]…[/emphasis]`, `[rate:0.85]…[/rate]`, `[pitch:+2st]…[/pitch]`, `[emotion:confident]…[/emotion]`, `[phoneme:…]…[/phoneme]`, `[gesture:point-right]`, `[look:camera]`, `[breath]`.
Парсер — отдельный пакет `packages/director-markup` с полным покрытием тестами (это ядро D1). Выход парсера: AST → компиляция в SSML провайдера + `gesture_cues.json`.

## Статусы рендер-джоба
`queued → preprocessing → tts → lipsync → compositing → encoding → done | failed | cancelled`. Каждый переход — событие в БД + WebSocket пользователю.

## Тестирование
- Unit: кредиты, hash сцен, парсер Director Markup, RBAC — покрытие ≥ 85%.
- Integration: testcontainers (Postgres, Redis, MinIO).
- E2E: Playwright, сценарий «регистрация → шаблон → правка → рендер → скачивание».
- Ни один PR без тестов на затронутую логику.

## Что НЕ делать
- Не реализовывать свои ML-модели — только интерфейсы + адаптеры к API.
- Не делать 4K, альфа-экспорт, Photo Avatar, коллаборативное редактирование, перевод видео — это фазы 2+.
- Не хардкодить ключи провайдеров — всё через env + конфиг-схему с валидацией (zod).
- Не изобретать стеганографию — C2PA-манифест через c2pa-node, невидимая метка — фаза 2.

## Порядок работы
Задачи выполняются по `docs/PLAN.md` строго по этапам. Каждый этап заканчивается работающим состоянием (`pnpm dev` поднимает всё, тесты зелёные). Перед стартом этапа — короткий план в issue/комментарии, после — что сделано и что отложено.
