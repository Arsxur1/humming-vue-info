# PLAN.md — этапы разработки AvatarStudio (для Claude Code)

Каждый этап — одна или несколько сессий Claude Code. Не начинать следующий, пока текущий не в состоянии «поднимается и тесты зелёные».

## Этап 0. Скелет монорепо (1 сессия)
- pnpm workspaces: `apps/web` (React+Vite+TS), `apps/api` (NestJS), `apps/worker` (BullMQ consumer), `packages/shared` (типы, zod-схемы), `packages/director-markup`.
- docker-compose: Postgres, Redis, MinIO.
- CI: lint + typecheck + test (GitHub Actions).
- **Готово, когда:** `pnpm dev` поднимает web+api, healthcheck зелёный.

## Этап 1. Auth + Workspaces + RBAC (1–2 сессии)
- Регистрация e-mail/пароль, JWT (access 15 мин / refresh), верификация e-mail (заглушка-логгер вместо SMTP).
- Workspace → участники → роли Owner/Admin/Editor/Reviewer/Viewer. Матрица прав как данные, не как if-ы.
- Аудит-лог (append-only таблица).
- **Готово, когда:** e2e-тест: регистрация → создание workspace → приглашение → проверка запрета действия для Viewer.

## Этап 2. Director Markup парсер (1 сессия) ← можно параллельно с этапом 1
- Пакет `packages/director-markup`: токенизатор → AST → валидация (вложенность, неизвестные теги, границы значений) → компиляторы: (а) в SSML, (б) в gesture_cues.json, (в) в plain text.
- Человекочитаемые ошибки с позицией в тексте.
- Покрытие ≥ 95%, property-based тесты на устойчивость к мусору.
- **Готово, когда:** все примеры из ТЗ FR-3.6 парсятся, фаззинг не роняет парсер.

## Этап 3. Модель данных проекта + CRUD (1–2 сессии)
- Таблицы: projects, scenes, layers (JSONB), versions (снимки, ≥30, diff), assets.
- Presigned upload в MinIO, антивирус-заглушка, транскодинг превью изображений.
- Автосохранение: PATCH сцены дебаунсом, оптимистическая блокировка (version counter).
- **Готово, когда:** интеграционный тест: создать проект из 20 сцен, править, откатить версию.

## Этап 4. Пайплайн рендера с mock-провайдерами (2–3 сессии) — ЯДРО
- Интерфейсы `ITTSProvider`, `IAvatarDriver` в `packages/shared`.
- **MockTTS**: генерирует тишину нужной длительности + синтетический alignment (равномерный по словам). **MockAvatarDriver**: возвращает статичное видео-заглушку аватара с таймкодом.
- DAG в worker: preprocessing → tts → lipsync → compositing (FFmpeg: фон + аватар + текстовые слои + субтитры из alignment) → encoding → S3.
- Статусы + прогресс через WebSocket. Отмена. Retry ×2 на транзиентных ошибках.
- **Scene-cache**: content_hash → таблица scene_render_cache; тест «правка 1 сцены из 20 → 1 пересчёт».
- **Кредиты**: резервирование/списание/автовозврат — транзакционно.
- **Готово, когда:** e2e: проект из 3 сцен рендерится в связный MP4 c субтитрами; повторный рендер без правок = 0 работы воркеров.

## Этап 5. C2PA + модерация + шаринг (1–2 сессии)
- C2PA-манифест (c2pa-node) как обязательный шаг encoding — рендер без него падает.
- Модерация скрипта перед постановкой в очередь: интерфейс `IModerationProvider`, первая реализация — вызов LLM-judge API + стоп-словарь. Очередь ручной модерации (таблица + admin-эндпоинты).
- Шаринг по ссылке: public / password / members, TTL.
- **Готово, когда:** тест: скрипт из стоп-листа не попадает в очередь; готовый MP4 содержит валидный манифест (проверка c2pa-инструментом).

## Этап 6. Редактор (3–5 сессий, самый большой фронтенд-этап)
- Canvas на PixiJS: сцена, слои (фон/аватар-плейсхолдер/текст/изображение/фигура), drag/resize/rotate, привязка к сетке, safe-zone.
- Панель сцен, таймлайн (без ключевых кадров — только длительности и порядок), переходы cut/fade.
- Панель скрипта с кнопками вставки Director Markup тегов.
- Мультиформат: 16:9 / 9:16 / 1:1 с раздельным хранением кадрирования.
- Превью-рендер одной сцены (кнопка → job → плеер).
- **Готово, когда:** Playwright: собрать 3-сценный проект в редакторе и отправить в рендер.

## Этап 7. Подключение реальных провайдеров (1–2 сессии + ручная регистрация ключей)
- Адаптер реального TTS API (выбор — по ADR после сравнения; кандидаты сравнить по: alignment, эмоции, языки, цена, лицензия).
- Forced-aligner шаг (MFA в docker) для провайдеров без фонемного alignment.
- Адаптер реального avatar/lipsync API.
- Замер: себестоимость минуты (логировать GPU/API-затраты по джобу в таблицу job_costs).
- **Готово, когда:** реальное 1-минутное видео с реальным голосом и липсинком; в БД лежит его фактическая себестоимость.

## Этап 8. Биллинг + тарифы (1–2 сессии)
- Кредитная модель по FR-10.1 (таблица множителей — конфиг в БД).
- Stripe: checkout, вебхуки, инвойсы. Free-тариф: 3 кредита, watermark (FFmpeg overlay), лимиты.
- Дашборд потребления по участнику/проекту.

## Этап 9. Шаблоны + консольный минимум админки
- Шаблоны с плейсхолдерами {{var}}, сохранение проекта как шаблон.
- Сиды: 10–15 стартовых шаблонов.

## Отложено сознательно (не трогать без решения)
Instant Avatar и Voice Cloning (consent-flow — фаза 2, требует юриста), перевод видео, bulk CSV, публичный API v1, SSO/SCIM, on-prem, Temporal-миграция.
