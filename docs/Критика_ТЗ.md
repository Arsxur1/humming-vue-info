# AvatarStudio — Критика ТЗ v2.0 и уточняющие вопросы
**Исполнитель:** Fable 5, роль — техдиректор/главный архитектор
**Дата:** 11.07.2026
**Статус:** Шаги 1–2 по разделу 0.2. ADR-пакет — после ответов на вопросы.

---

## 1. КРИТИКА ТЗ

### 1.1 Главное противоречие: трилемма NFR-1 × NFR-6 × NFR-14

Три требования, каждое разумное по отдельности, вместе образуют трилемму, которая на сегодня **не решается ни одним известным открытым стеком** [оценка]:

| Требование | Что требует | Кто это умеет |
|---|---|---|
| NFR-6: липсинк «не хуже референса», MOS ≥ 4.2 | Диффузионный класс моделей (EMO/Hallo/EchoMimic-класс) или проприетарные пайплайны | Диффузия или закрытые модели |
| NFR-1: рендер ≤ 1.2× длительности | Скорость близкая к реальному времени | Wav2Lip-класс, GAN-пайплайны |
| NFR-14: себестоимость ≤ $0.12/мин 1080p | Дешёвый инференс | Wav2Lip-класс |

Числовая иллюстрация [оценка, требует замера в Ф0]: диффузионные talking-head модели генерируют порядка 0.05–0.5 fps на A100. Одна минута видео 25 fps = 1500 кадров → от ~50 минут до ~8 часов GPU-времени A100 → **$3–30 себестоимости за минуту** при $3–4/час — превышение NFR-14 в 25–250 раз и NFR-1 в 50–500 раз. Wav2Lip-класс проходит NFR-1/14, но не проходит NFR-6 против референса 2026 года.

**Вывод:** референс, по всем признакам, достигает качества проприетарными моделями и годами их оптимизации (дистилляция, TensorRT, специализированный тренинг на своей библиотеке аватаров). Догнать его открытым стеком за Ф0+Ф1 — **[допущение с высокой вероятностью ложности]**.

**Что делать:** Ф0 как stop-gate — правильно, но в него нужно заложить **три ветки**, а не одну:
- A. Открытые модели + собственная оптимизация (дёшево, долго, риск не пройти NFR-6);
- B. Лицензирование коммерческого API липсинка/аватара как **постоянного** решения, а не запасного (быстро, маржа падает, NFR-14 надо пересматривать в ~$0.3–0.8/мин [оценка]);
- C. Гибрид: коммерческий API на запуск + параллельный R&D своей модели с миграцией по мере готовности.
Рекомендую C. Тогда NFR-14 разбивается на два значения: «на запуске» и «через 12 месяцев».

### 1.2 Противоречие: «паритет с HeyGen на момент запуска» vs объём Ф1

«Не ниже HeyGen на момент запуска» — это паритет с продуктом, который строился ~7 лет командой в сотни инженеров с проприетарным ML. При этом Ф1 = 12–16 недель. Эти два утверждения несовместимы. Честная формулировка цели: **паритет в core-loop** (скрипт → аватар → видео на уровне качества, неотличимом для целевого сценария L&D/обучение) + превосходство в D1–D4, и **осознанный не-паритет** во всём остальном на запуске. Если заказчик настаивает на буквальном паритете — сроки Ф1 умножаются на 3–4 [оценка].

### 1.3 Противоречие: on-prem (D3) vs гибридная TTS-стратегия

Раздел 5.3 рекомендует коммерческие API для Tier 1. FR-9.1 требует on-prem с локальными весами. Эти требования несовместимы для on-prem клиентов: в закрытом контуре коммерческого API нет. Следствия:
- либо on-prem версия работает **только** на собственных моделях (качество Tier 1 ниже SaaS — надо честно зафиксировать в матрице качества),
- либо on-prem требует лицензирования весов у TTS-вендора (единичные вендоры на это идут, ценник — шести-семизначный [оценка]),
- либо D3 сдвигается до момента, когда своя модель догонит API.
Это решение **меняет архитектуру** (абстракция инференс-слоя, packaging моделей) и должно быть принято до Ф1, а не в Ф5.

### 1.4 Лицензии открытых моделей — блокер, не упомянутый в ТЗ

Кандидаты из 5.3 в значительной части **непригодны для коммерческого SaaS** [факт на дату моих данных, требует перепроверки на дату старта]:

| Модель | Лицензия | Коммерческое использование |
|---|---|---|
| XTTS-v2 | Coqui Public Model License | **Запрещено** без отдельного соглашения (Coqui как компания закрылась — с кем договариваться, вопрос открытый) |
| Fish-Speech | Веса CC-BY-NC-SA | **Запрещено** |
| F5-TTS | Код MIT, веса CC-BY-NC | **Запрещено** для весов |
| StyleTTS2 | MIT | Разрешено, но датасеты голосов — отдельная проверка |

То же касается ряда talking-head моделей. В ADR по выбору моделей колонка «лицензия» должна быть **первым** фильтром, до качества. Пробел ТЗ: нет требования юридической проверки происхождения обучающих данных для моделей, которые мы дообучаем сами.

### 1.5 Требования с недооценённой трудоёмкостью

| Требование | Недооценка | Обоснование |
|---|---|---|
| FR-2.1: 100 стоковых аватаров на запуске | **×10–30** | Каждый аватар = кастинг, договор на образ (perpetual, worldwide, синтетика — юридически нетривиально), студийная съёмка idle + жестовой библиотеки под регламент 8.2, калибровка, QA на 15 языках. 100 аватаров = производственная студия на месяцы. Реалистично на запуск: 20–30 своих + возможное лицензирование |
| FR-3.1: 400 голосов | **×3–5**, если своя TTS | С коммерческим API — достижимо (это их каталог), но см. 1.3. Со своей моделью — 400 голосов это 400 записанных и очищенных дикторских сессий или синтетических идентичностей с проверкой прав |
| FR-3.9: phoneme-level alignment как жёсткий фильтр | Сужает выбор до 2–3 вендоров | ElevenLabs-класс отдаёт посимвольные тайминги, Azure — visemes; «полная эмоциональная палитра + cross-lingual клон + 60 языков + фонемный alignment» в одном вендоре не существует [факт на дату данных]. Реалистично: alignment добирается отдельным forced-aligner (MFA/ctc-segmentation) поверх любого TTS — это надо явно заложить в пайплайн |
| FR-7: перевод видео | **×2–3** | Релипсинк реального спикера «в дикой природе» (повороты головы, руки у лица, компрессия) сложнее, чем липсинк студийного аватара. Это отдельный продукт с отдельным Ф0-гейтом |
| FR-11.3: стеганографическая метка, устойчивая к перекодированию и обрезке | Research-уровень | Свою не писать; лицензировать существующее решение или сузить требование до «устойчива к типовому перекодированию» |
| FR-6.1: 150 шаблонов | ×3 | Это контент-продакшн с дизайнерами и методистами по 12 доменам. На запуск: 40–50 в 4–5 доменах (L&D, комплаенс, онбординг, продажи) |
| NFR-11: полная локализация UI на 12 языков включая биллинг и письма | ×2 | На MVP: EN + RU + 2–3 языка стартовых рынков; остальное после стабилизации строк |

### 1.6 Недостижимые или неизмеримые в заявленном виде метрики

| Метрика | Проблема | Предложение |
|---|---|---|
| NFR-6 «sync-score не хуже референса» | У референса нет публичных LSE-C/D; замер — на видео из их продукта, что легально серо и методологически шатко (их постобработка влияет на скор) | Зафиксировать абсолютные пороги: LSE-C ≥ X, LSE-D ≤ Y, измеренные на нашем бенчмарк-наборе + слепые парные сравнения «наше vs референс» на панели ≥ 30 оценщиков на язык |
| MOS-панели на 60 языках | Кто оценивает узбекский, тамильский, суахили с достаточной выборкой? | Tier 1 — полные панели; Tier 2–3 — прокси-метрики (WER обратного ASR, фонемные ошибки) + точечные носители через краудсорс |
| 15.2 п.7: scene-cache hit-rate ≥ 40% как критерий приёмки | Hit-rate — свойство поведения пользователей, его нельзя «сдать» до запуска | Перенести из приёмки в продуктовую метрику 90-го дня; в приёмке оставить: «правка 1 сцены из 20 пересчитывает 1 сцену» (это тестируемо) |
| NFR-5: 99.9% на MVP | Дорого и не нужно на старте | 99.5% до первого Enterprise-контракта |
| FR-2.5 «технически невозможно обойти» consent-gate | Недостижимо буквально: верификацию согласия можно атаковать теми же дипфейками | Переформулировать: liveness-детекция + контрольная фраза + аудит-трейл + порог стоимости атаки; «невозможно» заменить на «red team не проходит за N часов при бюджете M» |

### 1.7 Существенные пробелы

1. **Экономика злоупотреблений.** Free-тариф + бесплатное превью голоса (30/час) + бесплатные превью сцен (50/день) = бесплатная TTS/рендер-ферма. Нужны: device fingerprinting, лимиты на воркспейс И на пользователя И на карту, прогрессивная капча.
2. **Права на образы стоковых аватаров** — договорная конструкция с актёрами (вечная лицензия на синтетическое использование, отзыв, смерть актёра) не описана. Это критический путь Ф1, юрист нужен до съёмок, а не «до релиза Ф2».
3. **CDN/egress в юнит-экономике.** NFR-14 включает CDN, но видео-egress при успехе продукта может съесть больше GPU [оценка]; хранение ≥ 180 дней бесплатно (FR-5.8) при 4K — нужна политика lifecycle (переливка в cold storage).
4. **Платёжная география.** «Локальные провайдеры на приоритетных рынках» — не названы рынки. Если среди стартовых рынков РФ/СНГ — Stripe не работает, санкционные и комплаенс-риски меняют и биллинг, и юрструктуру. Это вопрос заказчику, не исполнителю.
5. **Музыкальная библиотека** (FR-4.7) — лицензирование royalty-free каталога не оценено.
6. **GPU-capacity стратегия** упомянута в рисках, но нет требования к резервированию под Ф0-замеры и под пиковые батчи bulk-generation (FR-6.4: 500 видео одним CSV — это управляемый DDoS собственной очереди; нужен отдельный rate-plan).
7. **Команда и бюджет** — в ТЗ отсутствуют полностью, при этом от них зависит реалистичность всех фаз. Верну оценку в артефактах, но допущения будут широкими, пока нет ответа на В-1.
8. **Interactive Avatar (Ф6)** архитектурно влияет на Ф1: если реалтайм в горизонте — инференс-слой надо проектировать stream-first уже сейчас, иначе переписывание. Дешёвая страховка: контракт инференс-API с поддержкой чанков.

### 1.8 Что вырезать из MVP ради скорости — и цена

| Вырезать/сократить | Из | Цена решения |
|---|---|---|
| 100 → 25 аватаров | FR-2.1 | Меньше витрина; компенсируется качеством и фильтрами. Восстановление: +5–10/мес после запуска |
| 400 → ~120 голосов (Tier 1 полностью, Tier 2 частично) | FR-3.1 | Tier 3 языки объявляем по мере прохождения замеров, «честная матрица качества» из Части 17 это уже легитимизирует |
| 150 → 45 шаблонов, 5 доменов | FR-6.1 | Домены «медицина/фарма, финансы, госсектор» требуют экспертизы — переносим в Ф2–Ф3, D2 не теряется, а фокусируется |
| 4K и альфа-экспорт | FR-5.5/5.6 | Почти нулевая потеря для персон MVP; 4K — маркетинговая строчка, вернуть в v1.x |
| Photo Avatar | FR-2.8 | Низкое качество на старте бьёт по восприятию бренда; вернуть в Ф2 вместе с клонами |
| Совместное редактирование | FR-4.11 | И так S; подтверждаю перенос |
| Keyframe-анимация слоёв | FR-4.3 частично | Оставить пресетные анимации FR-4.5; полноценные ключевые кадры — v1.x. Экономия ~3–4 недели фронтенда |
| Локализация UI: 12 → 4 языка | NFR-11 | RTL-архитектуру заложить сразу (дешево), сами переводы — после заморозки строк |

**Не вырезать ни при каких условиях** (подтверждаю раздел 0.3): consent-gate, C2PA, модерация, scene-cache (D4 — это и наша экономика тоже), Director Markup (D1, дешевле остальных дифференциаторов в реализации, так как ложится на TTS-пайплайн).

## 2. УТОЧНЯЮЩИЕ ВОПРОСЫ (12)

Только те, что меняют архитектуру или экономику.

1. **Бюджет и команда.** Какой диапазон бюджета на первые 12 месяцев и есть ли уже ML-инженеры? Ответ определяет ветку A/B/C из п. 1.1 сильнее любых технических аргументов.
2. **Допустимая маржа на запуске.** Готовы ли работать при себестоимости $0.4–0.8/мин на коммерческих API первые 6–12 месяцев (ветка C), или NFR-14 ($0.12) — жёсткое условие дня 1 (тогда ветка A и риск провала NFR-6)?
3. **Стартовые рынки — назовите 2–3 страны.** От этого зависят: платёжные провайдеры, резидентность данных, приоритет языков UI, юрисдикция юрлица. Отдельно: **входит ли РФ/СНГ в стартовые рынки?** (меняет биллинг и комплаенс фундаментально).
4. **Буквальность паритета.** Принимается ли формулировка «паритет в core-loop + осознанный не-паритет в периферии» (п. 1.2)? Если нет — фазы пересчитываются.
5. **On-prem: подтверждаете ли, что on-prem версия может иметь качество Tier 1 ниже SaaS-версии** (следствие п. 1.3)? Или D3 сдвигается до готовности собственных моделей?
6. **Стоковые аватары: своя съёмка, лицензирование готовой библиотеки или гибрид?** (Часть 19 п. 7 — но мне нужен ответ до Ф1, это критический путь.) Есть ли доступ к съёмочным мощностям/актёрам на приоритетных рынках?
7. **Есть ли существующие отношения/предконтракты с TTS- или аватар-вендорами**, NDA, стартовые скидки? Наличие меняет shortlist в ADR.
8. **Interactive Avatar (Ф6): это «когда-нибудь» или в горизонте 18 месяцев?** Если второе — инференс-контракт проектируется stream-first с Ф1 (+2–3 недели к Ф1, минус переписывание потом).
9. **Кто целевой первый платящий сегмент MVP: L&D Enterprise или SMB-маркетолог?** Персоны перечислены все сразу; порядок выхода меняет приоритет FR-6.4 (bulk), FR-8 (API) и тарифную сетку.
10. **Требование к резидентности данных на запуске:** один регион (какой?) или сразу мультирегион? Мультирегион с первого дня удорожает Ф1 на ~25–30% [оценка].
11. **Ф0-бюджет на GPU и данные:** есть ли ~$15–30k [оценка] на замеры (аренда A100/H100, лицензии тестовых API, панели оценщиков)? Без этого stop-gate не будет доказательным.
12. **Кто владелец решения по стоп-листу публичных лиц и модерационной политике** (юрист/траст-энд-сейфти на стороне заказчика или нанимаем)? SLA 24 ч по FR-11.6 требует дежурной функции — чьей?

## 3. РЕКОМЕНДАЦИИ ПО ЧАСТИ 19 (открытые вопросы заказчика)

| № | Вопрос | Рекомендация |
|---|---|---|
| 1 | Свой инференс vs API | **Гибрид C** (п. 1.1): API на запуск для скорости и качества, параллельный R&D своей модели для маржи и on-prem. Триггер миграции: своя модель проходит NFR-6 на Tier 1 в слепом тесте |
| 2 | Облако | Гипермасштабируемый (AWS/GCP) для control-plane + специализированный GPU-провайдер (CoreWeave/Lambda-класс) для инференса. Мультиоблачность GPU с первого дня — это и есть митигация дефицита |
| 3 | Стартовые рынки | Нужен ваш ответ (В-3); техрекомендация: не более 3 языков Tier 1 «эталонного» качества на день 1, остальные Tier 1 — в течение первого квартала |
| 4 | On-prem сразу или после Ф3 | **После Ф3**, но с двумя дешёвыми страховками в Ф1: (а) весь инференс за единым внутренним API-контрактом, (б) никакой бизнес-логики в managed-сервисах, которых нет в self-hosted варианте |
| 5 | Монетизация | Кредиты (как в ТЗ) для SMB/Creator + seats с пулом кредитов для Team/Business. Чистые минуты понятнее, но убивают маржу на превью/черновиках; чистые seats не защищают от тяжёлых пользователей |
| 6 | Мобильное приложение | Не нужно в первый год. Веб-редактор desktop-first + мобильный просмотр/шаринг (PWA). Данные референса подтверждают: создание — desktop-сценарий |
| 7 | Аватары: съёмка vs лицензия | Гибрид: лицензировать 15–20 для скорости запуска + снять 10–15 своих в приоритетных доменах (медицинская форма, деловой стиль под L&D) как начало рва. Полностью лицензированная библиотека — не ров, полностью своя — не успеем |
